# 实施顺序

第 0 步和第 1 步已完成；以下功能均未实现。以可体验和可验证的结果推进，不预先承诺开发周数。

| 步骤 | 交付 | 验收 |
| --- | --- | --- |
| 0. 范围与契约（已完成） | 产品、架构、NPC 文档；事件/动作/实时协议 Schema；有效与无效示例 | 关键语义明确，基础结构校验通过 |
| 1. Game shell（已完成） | React + Phaser 4 + Vite；图书馆地图、玩家、碰撞、移动、座位、GameBridge | 可以进入图书馆走到桌前坐下，React 面板可开关 |
| 2. 真实专注闭环 | FastAPI、PostgreSQL、迁移；身份边界；项目、任务、专注、进度板；事件事务、快照和 WebSocket | 刷新恢复计时；暂停不计时；重复请求不重复累计；重启记录仍在 |
| 3. NPC simulation | 两个人物档案、现实时间作息、状态机、移动、工作与休息、简单关系规则 | 无模型也能自主活动，事件可追踪 |
| 4. Agent 与长期记忆 | perception、检索、policy、模型适配、动作执行、持久记忆、决策记录 | 跨会话记忆；安全拒绝非法动作；空闲互聊；专注中不主动打断 |
| 5. 第一版发布准备 | 素材许可清单、错误提示、认证、备份、恢复验证、性能与模型成本测量、部署方案 | 一位真实用户从进入到复访的完整流程稳定可用 |
| 第二阶段 | 好友邀请、房间权限、在线状态、协作看板 | 两位用户看到一致状态，私人数据与共享数据边界清晰 |

## 第一个端到端切片

一张地图，一个玩家，两个 NPC，一个项目，一个任务，一次 25 分钟会话。先用一个无模型也有价值的专注流程，再补 NPC 认知能力。不要把所有模块同时铺开成未完成的占位实现。

## 下一次实现的具体范围

落实第 2 步：加入 FastAPI 与 PostgreSQL，先完成项目、任务、FocusSession、单用户身份边界及持久 World Event。React 以 REST 读取和修改任务；计时以服务端时间为准，刷新后恢复。视觉资源目前均为程序绘制的可替换占位风格；不显示伪造的持久化、NPC 记忆或联机成功状态。

## 实现前仍需确定

美术资源采用自制、授权素材还是生成资源；模型提供方与预算；公开使用时的认证与部署环境。这些不阻塞文档、契约和本地游戏壳，分别在接入对应功能前决定。
