# 产品范围

## 目标

让用户进入一个安静、有人陪伴的像素图书馆，选择真实任务，完成专注，并留下可持续追踪的项目进展。NPC 拥有自己的生活，不要求玩家不断回应。

## 第一版边界

网页版，单人私人世界，两个 NPC 起步，最多三个。用户身份和世界隔离从数据库设计开始保留；本地开发可使用固定测试用户，但任何公开部署前必须接入认证与资源归属校验。

包括：一个可行走、有碰撞与可交互座位的图书馆；固定玩家外观；项目和任务增改、任务状态、专注计时、项目进度板；NPC 作息、移动、阅读或工作、休息、对话、长期记忆及 NPC 之间的互动。

第二阶段：好友邀请、房间成员、实时在线状态、共享项目权限、多人座位竞争。

预留而不实现：家和咖啡馆等地点、外观装备槽、家具定义、天气表现、场景切换入口。公司作为未来地点类型。预留字段不代表首版提供这些功能，不建空 API 或虚假按钮。

不做：开放世界、大量 NPC、经济系统、语音、战斗、自动生成地图、NPC 自改提示词或写代码。

## 首条完整体验

1. 进入图书馆，读取服务器快照，看到玩家和按当前现实时间活动的 NPC。
2. 走到书桌并坐下，React 打开任务选择面板。
3. 创建或选择项目与任务，设置专注时长（默认 25 分钟）。
4. 后端确认专注开始后，倒计时运行，玩家播放工作动画，看板显示正在进行的任务。
5. NPC 按自己的安排活动。可能安静地回应重要事件，但专注中默认不主动打断玩家。
6. 完成专注后记录实际有效时长。用户决定是否把任务标为完成。
7. 刷新或第二天回来，项目、专注历史和 NPC 记忆仍在。

## 专注规则

- 一个用户同时最多一个未结束会话，暂停也占用该名额。
- 状态：active → paused → active；active / paused → completed 或 cancelled。结束后不可重复累计。
- 服务端保存开始、暂停、恢复和结束时间及累计有效秒数。浏览器倒计时只是显示，切后台或刷新不影响计时。
- 暂停不累计时长；达到目标后完成，由服务端进行到期检查及请求时校正。断网期间计时继续，结束后可通过快照恢复；未确认的操作显示待同步或失败。
- 提前结束明确记为 cancelled，保留已完成的有效秒数，单独展示中断状态；不冒充完成目标。
- 计时完成不自动完成任务；完成任务也不自动关闭其他会话。
- 时间戳使用 UTC、带时区。用户设置的 IANA 时区控制本地日界线、现实时间显示及 NPC 作息，默认可从浏览器获得。

## 项目进度板

展示项目、任务状态、当前专注、今日和累计专注时长、已完成任务数 / 总任务数。任务进度与投入时间分别展示，没有任务时展示“暂无任务”，不计算无意义百分比。

首版仅本人可见，NPC 对项目的感知按允许公开给 NPC 的事件字段投影；不默认把任务全文或私人对话广播给未来房间成员。

## 验收底线

- 不依赖 LLM，也能完成进入、坐下、选任务、专注、结束、查看记录的流程。
- 刷新、重复点击、断线重连不产生重复会话或重复时长。
- NPC 至少有两个可观察的自主活动，会在空闲时互相互动；模型失败仍能继续作息。
- 至少一条真实对话记忆在重启后被检索并恰当地使用；未发生的用户经历不能作为事实记忆。
- 被拒绝的 NPC 动作不会改变世界，能通过决策记录查到原因。
